# Third-party licenses

FR-SEC-10: an inventory of every Python package this project depends on, direct and
transitive, with the license each one declares. Checked 2026-09-30 against the packages
actually installed by `pip install -e .` (runtime) and `pip install -e ".[dev]"` (dev), on
Python 3.12. `tests/test_licenses.py` keeps the **direct** dependencies below in sync with
`pyproject.toml`; it does not re-verify license text or re-resolve transitive versions, so
re-run the commands in this file's own note after any dependency change and update it by hand.

No package below is copyleft in a way that would require releasing this project's own source
(no GPL/AGPL/LGPL). Every license is one a commercial, closed-source product can depend on
without extra obligations beyond keeping the package's own license notice with it (standard
practice; not itself embedded in this repository), **except** `certifi`, flagged below.

`[CONFIRM]` **certifi is MPL-2.0** (weak/file-level copyleft: modifying an MPL-covered file
and distributing that modification would require sharing the change; using it unmodified, as
here, carries no such obligation). It is pulled in only because `requests` depends on it — this
project does **not** use certifi's CA bundle: `http_utils.trust_context()` deliberately uses the
OS trust store or `--ca-bundle` instead (decision B1, SRS FR-CLI-06). Flagged for a pass by
someone with legal authority before commercialization, even though certifi is a very widely
used, unmodified dependency in this project.

## Checking again

```bash
pip install -e ".[dev]"
pip list --format=freeze          # every installed package and its resolved version
pip show <package>                # License / License-Expression, and Requires for that package
```

Run this after adding, removing or upgrading a dependency, and update the tables above by
hand — this file is not generated by a tool (no new dependency was added to build it, per
CLAUDE.md).

## Considered and not used

Decision D7 (2026-10-04): the TLS probes (`websec_scanner/checks/tls_probe.py`) are written in this
repository, with `socket` and `struct`, instead of embedding a TLS scanner.

- sslyze is AGPL-3.0: embedding it would oblige this project, and any hosted service built on it,
  to publish its own source.
- testssl.sh is GPL-2.0: bundling it with a closed product is not possible.

Neither is a dependency. The IANA TLS cipher suite registry is the source of the suite codes in
`websec_scanner/rules/tls_probe.json` (facts, retrieved 2026-10-04), not a package.
